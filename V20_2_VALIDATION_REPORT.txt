10. ROLE-SCOPED V20.2 READ APIs
-------------------------------
Hardened after review:
- `/api/v20.2/state` full enterprise state is limited to executive/sector/finance roles (system_owner remains the middleware super-role).
- `/api/v20.2/tasks` returns all tasks only to elevated management; non-elevated users require `X-User-Id` and receive only assigned-user or assigned-role tasks.
- `/api/v20.2/doctor-workspace` is separated from full state and requires the veterinary/executive role gate plus user identity for non-executives.
- `/api/v20.2/owner-workspace/:farmId` checks active V20.2 user scopes before allowing a farmer to read a farm workspace.
Assessment: PARTIAL security. These checks reduce data exposure but `X-User-Role` / `X-User-Id` are not cryptographically authenticated identities. A real authentication/session/JWT layer remains required before production.
